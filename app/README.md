# 소비기한 입고 검수 앱 (시연용)

카메라 앞에 상품을 대면 자동으로 촬영해 바코드와 소비기한을 읽고, 신뢰도가 낮은 건만 사람이 확인한 뒤
재고 DB에 기한 순으로 쌓습니다. 채점 대상이 아니며 `predict.ipynb` 와 패키지를 공유하지 않습니다.

## 실행

```bash
pip install -r requirements.txt -r app/requirements.txt
bash download_weights.sh
python -m uvicorn server:create_app --factory --app-dir app --port 8000
```

크롬에서 `http://localhost:8000/` 을 엽니다. 첫 판독은 모델을 올리느라 수십 초 걸릴 수 있습니다.

## 구조: 무엇이 어디서 도는가

| 위치 | 하는 일 | 이유 |
|---|---|---|
| 브라우저 (온디바이스) | 카메라, 프레임 차분 자동 촬영과 EAN-13 바코드 인식 | 가볍고 즉시 반응해야 함. 서버 비용 0 |
| 매장 PC 서버 | OCR 판독(`src/pipeline.py` 그대로), 신뢰도와 재고 DB | CPU 4코어에서 장당 약 1.5초. GPU와 인터넷 불필요 |

OCR이 장당 1.5초라 프레임마다 돌릴 수 없습니다. 그래서 물체가 들어와 멎는 순간에만 한 장을 보냅니다
(`static/motion.js`). 촬영 뒤에는 물건을 치울 때까지 다시 찍지 않습니다. 첫 판독은 모델을 메모리에 올리느라 수십 초가 걸릴 수 있으므로, 시연 전에 아무 사진이나 한 번 판독해 둡니다.

## 스캐너 트리거와 2단계 촬영 (09-28)

입고 검수대에는 바코드 스캐너가 이미 있습니다. 스캐너는 키보드 입력 장치라 숫자와 엔터를 보내고, 앱은 입력 칸에
포커스가 없을 때 숫자 8자리 이상 + 엔터를 받으면 바코드를 채우고 **즉시 촬영**합니다(스캐너가 없으면 숫자를 직접
치고 엔터를 눌러 같은 흐름을 시연할 수 있습니다).

| 촬영 | 서버 모드 | 재시도 범위 | 실측 |
|---|---|---|---|
| 1차 (스캔 직후) | `shot=first`, 싼 모드 | s1, s2, det5 까지 | 날짜 없음 판정 1.6초, 날짜 있으면 1.7초 |
| 2차 (날짜 면 재촬영) | `shot=second`, 전체 | 모든 재시도 단계, 장당 상한 8초 | 2.5초 (000575) |
| 스캐너 없이 자동 촬영 | `shot=full`, 전체 | 모든 재시도 단계 | 기존과 동일 |

1차에서 날짜가 없으면 폼을 열지 않고 "날짜 면을 보여 주세요"를 띄우고, 검수원이 상품을 돌려 대고 멈추면 프레임
차분이 2차 촬영을 합니다. 회전, 침식, 확대 같은 재시도 단계는 날짜가 화면에 있는데 안 읽힐 때 쓰는 것이라, 날짜
면이 아예 없는 1차 사진에 돌리면 8초를 낭비한 뒤에야 안내가 뜨기 때문입니다. 싼 모드는 `src/` 를 바꾸지 않고
`ocr.read_raw(stage_cap="cheap")` 를 앱에서 호출해 만듭니다. 채점 노트북의 동작과 속도는 그대로입니다.

2차 촬영이 필요했던 비율은 재고 화면 통계에 나옵니다(`second_shot`). 바코드 면과 날짜 면이 다른 상품(페트병,
캔, 상자 옆면)의 비율을 실측하는 용도입니다.

## 휴대폰으로 쓰기와 연속 스캔 (09-30)

휴대폰 브라우저는 https 에서만 카메라를 연다. PC 와 휴대폰을 같은 와이파이에 두고:

```bash
bash app/tools/make_cert.sh <PC의 IPv4 주소>          # 자체 서명 인증서 (app/.data, 커밋 안 됨)
python -m uvicorn server:create_app --factory --app-dir app --host 0.0.0.0 --port 8443   --ssl-keyfile app/.data/key.pem --ssl-certfile app/.data/cert.pem
```

휴대폰에서 `https://<IP>:8443` 접속, 경고 화면에서 계속, "스캔 시작". 윈도우 방화벽 창이 뜨면 허용한다.

흐름: 상품을 카메라 앞에서 돌리면 바코드는 0.5초마다 브라우저가 찾고, 소비기한은 손이 멎어 있는 프레임에서만
1.2초마다 서버로 판독한다(흔들린 프레임은 시도 횟수만 낭비하므로 건너뛴다, `static/motion.js`). 화면 위 두
칸(바코드, 소비기한)이 모두 채워지고 신뢰도가 기준 이상이면 완료음과 함께 자동 저장하고, 낮으면 그때만 확인
화면을 연다. 못 읽어도 멈추지 않는다: `first, first, mid, full` 순서를 계속 돌며 재시도한다(`static/retry.js`
의 `nextShot`). first 는 싼 모드(s1, s2, det5), mid 는 거기에 침식(erode5) 한 번을 더 보는 중간 단계, full 은
전체 재시도다. full 은 장당 최대 8초라 직전 full 로부터 6초가 안 지났으면 그 차례는 mid 로 대신한다. 2회
실패부터 "날짜 면을 보여 주세요", 한 바퀴(4회) 실패부터 "확인 버튼으로 직접 입력"을 안내하지만, 확인 화면은
날짜가 읽혔는데 신뢰도가 낮을 때나 사용자가 확인 버튼을 눌렀을 때만 연다. 의약품 GS1 2D 바코드(AI 17)에
유효기한이 있으면 OCR 없이 바코드에서 읽는다 (`static/gs1.js`). 진행 중인 상품과 다른 바코드가 보이면
진행 중이던 항목은 버리고 새 상품으로 전환한다.

할인 대상: 소비기한까지 남은 일수가 분류별 기준 이하인 상품 (`products.DISCOUNT_DAYS`: 신선 3일, 유제품 5일,
가공식품과 음료 21일, 의약품과 화장품 90일, 미등록 21일). 재고 화면 "할인 대상" 탭에서 옮긴 뒤 "옮김"을 누르면
빠지고, `GET /api/items.csv?discount=1` 로 목록을 내려받는다.

## 신뢰도 점수

학습 모델이 아니라 조회표입니다. 예측을 네 조건(처음 시도에서 풀렸나, 날짜가 완전한가, 만료 키워드 근거가
있나, 비슷한 점수의 다른 날짜 후보가 있나)으로 나누고, 골드 1,000장에서 같은 조건이었던 예측의 실제
정답률을 점수로 씁니다. 0.90 미만이거나 연, 월, 일 중 하나라도 못 읽었으면 화면에서 빨갛게 표시하고
사람이 확인합니다. 화면 배지의 퍼센트는 1,000장 전체로 만든 표의 값이므로, 성능 근거로는 아래 교차 검증
수치를 씁니다.

2폴드 교차 검증 (표를 만든 500장과 다른 500장에서 측정):

```
fold A: 자동 통과 363/500 (72.6%), 자동 통과 정답률 97.5%, 확인 대상 정답률 62.8%
fold B: 자동 통과 430/500 (86.0%), 자동 통과 정답률 95.8%, 확인 대상 정답률 70.0%
```

표를 다시 만들려면 `python app/tools/build_confidence_table.py`.

## 시연용 더미 데이터

`data/products.csv` 의 바코드와 상품명은 가짜입니다. 바코드로 상품명을 찾는 일은 매장 POS가 이미 하고
있으므로, 실제 도입 시에는 이 표 대신 POS 상품 마스터에 연결합니다.

## 소요 시간 측정

촬영 모드는 상품이 화면에 들어온 순간부터 저장까지, 수기 모드는 "시작"을 누른 순간부터 저장까지를
잽니다. 촬영 모드에는 상품을 집어 카메라 앞까지 가져오는 시간이 빠져 있으므로, 비교할 때는 수기 모드도
상품을 손에 든 상태에서 "시작"을 누릅니다. 재고 목록 화면 상단에 두 방식의 건당 평균과 단축 비율이
나옵니다. `GET /api/items.csv` 로 원자료를 받을 수 있습니다.

## 화면 목록

- `index.html` (스캔): 카메라로 상품을 촬영해 바코드와 소비기한을 인식하고 재고 DB에 저장합니다.
- `stock.html` (재고와 할인 대상): 저장된 상품을 기한 순으로 나열하고, 할인 대상(기준 미만 남은 일수)을 조회합니다.
- `verify.html`: 중고거래 게시글용 기한 검증입니다. 당근, 번개장터처럼 올리는 게시글 사진 최대 5장(소비기한 표시 부분이 보이는 사진 포함)으로 등록 가능, 등록 불가, 운영자 확인 판정을 합니다. 날짜를 읽은 사진 중 가장 빠른 소비기한(최저 기한)을 기준으로 판정하며, 기준 개월 수는 화면에서 입력받지 않고 서버 상수(`MIN_MONTHS`, 기본 6개월, 식약처 시범사업 초기 기준)로 고정합니다. 사진은 저장하지 않습니다. 서버는 전 사진을 싼 모드로 먼저 읽어 그 결과만으로 등록 불가가 확정되면 바로 끝내고, 아니면 날짜를 못 읽은 사진만 전체 모드로 다시 읽어 지연 시간을 줄입니다.
